当前已确认的问题：

4. 现有银行监听器的一部分处理只判断银行是否开局，没有限制操作者是否属于银行。禁止为解决新模块问题擅自改动原游戏；接入时先验证并发影响，必要时讨论同时运行限制。

## 目录与配置约定

```text
src/main/java/com/mlc/mlcgames/party/
  core/                         仅供新模块使用的公共能力
  <category>/<game_id>/          每个小游戏自己的逻辑
src/main/resources/party/
  <category>/<game_id>/
    language.yml
    locations.yml
    game.yml
```

部署时保留相同分类路径到插件数据目录。不得用所有游戏共用一张配置代替每游戏的三张配置。

`language.yml` 包括游戏名、玩法介绍、开始/结束/倒计时、淘汰/获胜、错误、道具名称和说明。玩家可见文字引用语言键；占位符有明确列表。

`locations.yml` 包括地图列表、世界名、地图区域对角两点、等待/返回/旁观位置、玩家/队伍出生点和该游戏必需的特殊区域或点位。新地图坐标保持 `null`，世界名保持空串；不能使用 `(0,0,0)` 伪装已配置。`configured: false` 只是额外显式开关，设置为 true 后仍须逐项验证所有坐标。区域可反向选点，程序归一化最小/最大坐标。触及世界高度、非有限数值、不同世界、越界特殊点和不合理体积时拒绝启动并说明路径。

地图区域指包含所有游戏活动的三维长方体；地板区域、门区、目标区、模板区各有自己的两个角点。模板区允许位于比赛区外，但必须明确声明，不能借区域配置修改任意世界位置。

`game.yml` 包括启用状态、人数范围、倒计时、总时限、轮次、模式、计分、胜负、物品与效果、地图恢复限制和源码对应说明。不同模式若共享实现，应保留各自独立配置目录及模式标识。

参考形态（仅规范示例，不是已完成的游戏配置）：

schema-version: 1

涉及破坏、放置、爆炸和生成的玩法需记录本局改动，按本局快照恢复方块状态和容器内容；不依赖用户重新粘贴原地图。区域体积及每 tick 修改量设限，拒绝超限配置。含模板/结构生成的玩法允许配置建好的模板区或用户提供的结构资源。禁用附带原命令的复制与执行。

## Wool Wars 采用的方案（非原地图已完成规则）

- 两队，默认各 4 人，至少各 1 人，人数上限可配置；人数不均时优先均衡，不强塞多余玩家。
- 中心目标区默认 3×3，允许配置尺寸。先清除中立方块，再放入本队羊毛；全部被同队占满时该队赢下本回合。
- 每回合死亡后旁观，下一回合复活；全队淘汰则另一队赢回合。
- 默认每回合 120 秒，超时比较中心目标区占有数量，相同为平局。默认先赢 3 回合结束整局，允许配置。
- 首版为统一基础装备；不自行增加未获确认的职业和技能。仅可破坏中心目标和本局玩家放置的方块，不可拆除其他场景。
- 出生点、观战点、目标区两个角点、允许放置区两个角点、等待与返回位置均配置；每回合恢复目标区及玩家改动，结束时完整清理。
- 整局胜队按派对配置计分。队伍中途退出导致一方无人则判该方弃权；双方都无人则取消。

用户后续同意继续，已按本方案加入独立注册表；尚待新地图实机验证。
